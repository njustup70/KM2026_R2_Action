# PathChaser

`PathChaser` 是一个轻量路径跟踪库。  
输入是一组离线路点（包含位置、姿态、前馈平移速度、前馈角速度、时间戳），输出是当前时刻“建议控制量”。

本模块 **不直接控制底盘**，只负责 **产出命令**；上层可自行决定如何使用这些命令。

## 使用示例

    // 由用户决定是否直接下发，或用作其他用途

## 数据结构

## 路点

```cpp
struct PathWaypoint
{
    Vec2 pos;       // 位置（m）
    float yaw_rad;  // 朝向（rad）
    Vec2 vel_vec;   // 前馈平移速度（m/s）
    float omega_rad;// 前馈角速度（rad/s）
    float t_sec;    // 时间戳（s）
};
```

## 路径

```cpp
template <size_t waypointCount = 256>
class Path
{
public:
    PathWaypoint waypoints[waypointCount];
};
```

说明：
- `Path` 是编译期定长数组，避免动态分配。
- 建议按 `static const Path<N>` 方式定义，减小 RAM 压力。

## 跟踪逻辑

每个周期主要流程如下：

1. 用当前位置对整条路径做最近点投影，得到实测进度 `s_meas`
2. 在 `s_meas` 前方取一个前瞻点 `s_cmd`
3. 从 `s_cmd` 采样路径局部几何，得到切向 `T`、法向 `N`、曲率 `kappa`
4. 只用法向误差做主反馈，避免把整个位移误差直接拉向某个目标点
5. 切向速度由前馈速度和曲率限速决定，姿态由路径点规划的 `yaw_rad / omega_rad` 加反馈决定
6. 终点判定只看末端几何误差和保持时间，不再依赖时间严格对齐

可以把它理解成一个“预瞄式 Frenet 跟踪器”：

- `s_meas` 负责告诉控制器“我现在离路径哪里最近”
- `s_cmd` 负责往前看一点，避免反应太迟钝
- `v_t` 负责沿曲线前进
- `v_n` 负责把车拉回曲线
- `omega` 负责让车头跟随路径文件里规划好的任务朝向

核心公式大致是：

- `lookahead = clamp(_lookahead_min + _lookahead_gain * |v_ff|, _lookahead_min, _lookahead_max)`
- `s_cmd` 平滑跟随 `s_meas + lookahead`
- `v_t = clamp(dot(v_ff, T), 0, v_curve_limit)`
- `v_n = clamp(-_kp_pos * e_n, -_max_pos_fb, _max_pos_fb)`
- `omega = omega_ff + clamp(_kp_yaw * yaw_err, -_max_yaw_fb, _max_yaw_fb)`

如果路径本身是质量较好的平滑曲线，这种方式会比“追一个目标点”更贴线，也更不容易切弯。

## 调试参数说明

`PathChaser` 里这些成员变量，主要可以分成 4 组：

1. 路径跟随强度
2. 目标进度推进速度
3. 速度 / 角速度限幅
4. 完成判定条件

下面按“你改它会看到什么现象”的方式说明。

### 1. 路径跟随强度

#### `_kp_pos = 2.0f`
横向误差反馈增益。  
现在它主要作用在“法向误差”上，也就是把车从曲线左右两边拉回路径附近。

- 数值增大：车会更积极地往曲线中线拉回去，偏差修正更快
- 数值过大：容易出现横向抖动、过冲、拐弯时来回修正
- 数值过小：车会显得“跟不紧”，偏离路径后回正慢

这个参数主要影响的是：
- 路径贴合度
- 抗扰动能力
- 曲线边缘的回收速度

#### `_kp_yaw = 2.2f`
姿态误差反馈增益。  
作用是把“当前朝向和路径点规划朝向的误差”转换成补偿角速度。

- 数值增大：车头对齐更快，转向更果断
- 数值过大：容易出现原地甩头、朝向抖动、转角来回修正
- 数值过小：朝向跟随滞后，尤其是转弯或终点对姿态要求高时更明显

这个参数主要影响的是：
- 车头对向稳定性
- 转弯姿态收敛
- 终点朝向完成情况

#### `_max_pos_fb = 0.28f`
法向反馈速度上限。  
这是 `_kp_pos * e_n` 之后，单独给横向修正项做的限幅。

它的意义不是“提高速度”，而是防止位置误差太大时，反馈项直接把速度拉满，导致长期猛追。

- 数值增大：允许更强的位置纠偏
- 数值减小：纠偏更保守，轨迹更平滑，但回正更慢

如果你发现：
- 一偏离就猛冲
- 拐角处横向修正太激进

通常优先考虑减小这个值，而不一定先改 `_kp_pos`。

#### `_max_yaw_fb = 0.80f`
姿态反馈角速度上限。  
这是 `_kp_yaw * yaw_err` 之后的限幅。

- 数值增大：允许更快修正朝向
- 数值减小：朝向修正更平稳，但可能跟不上路径转向

如果底盘转头太猛、容易左右摆，先看它。

#### `_yaw_ff_degrade_range = 0.3f`
Yaw 前馈衰减范围，单位弧度。  
按代码里的设计意图，它本来是用于“yaw 误差较大时，逐步减小角速度前馈”的。

不过要注意：**当前实现里这段前馈衰减逻辑被注释掉了**，所以这个参数现在基本是预留项，不会直接影响控制输出。

如果后续把那段逻辑恢复了，它的含义会变成：
- yaw 误差小于该范围时，前馈逐步恢复
- yaw 误差大于该范围时，前馈趋近于 0

### 2. 进度与前瞻

#### `_k_sync_time = 0.0f`
预留的时间同步增益。  
在新的几何跟踪里，时间不再是主驱动，所以这个参数默认不参与主控制，只保留给兼容旧配置和后续扩展使用。

它的作用是：
- 如果后续想重新引入时间辅助，它可以作为很弱的辅助项
- 不建议让它重新变成主驱动，否则又会回到“按时间追点”的老问题

#### `_k_sync_meas = 4.0f`
进度平滑/跟随增益。  
这里的实测进度 `s_meas` 仍然是通过当前位置投影到路径上得到的，但它现在主要用于把前瞻点平滑地往前推。

它的作用是：
- 让前瞻点更稳，不会在曲线和噪声之间来回抖
- 让 `s_cmd` 不至于一步跳太猛

- 数值增大：前瞻点收敛更快，响应更跟手
- 数值减小：前瞻点更平滑，但路径响应会慢一点

### 3. 速度和角速度限幅

#### `_max_vel = 1.20f`
合速度上限。  
这是最终世界系线速度向量 `v_world` 的总长度上限。

注意它限制的是“合速度大小”，不是单独限制 `vx` 或 `vy`。

- 数值增大：允许更大的平动速度输出
- 数值减小：整条轨迹会更保守

如果底盘动力不足、轮子容易打滑、或者希望整体动作更稳，这个值是重要安全阀。

#### `_max_omega = 1.80f`
角速度上限。  
这是最终输出角速度 `omega` 的上限。

- 数值增大：允许更快转向
- 数值减小：转弯更平滑，终点姿态更稳

如果转向过激、姿态抖动、或者 IMU/控制链路还没调稳，建议先压低它。

### 4. 进度速度限制

#### `_max_s_dot = 1.00f`
进度平滑器速度上限。  
`_s_cmd` 仍然是“沿路径走到哪里”的内部控制量，但它现在只负责辅助前瞻，不再承担时间主导推进。

这个值决定路径追踪器最多允许自己“沿路径往前推多快”。

- 数值增大：前瞻更快，系统更激进
- 数值减小：前瞻更慢，系统更稳

如果你发现车身还没贴回曲线，前瞻点就跑得太快了，适当减小这个值。

#### `_min_s_dot = -0.15f`
控制进度速度下限。  
它允许 `_s_cmd` 在某些情况下轻微回退。

这个回退量主要是给“位置实测进度”和“前瞻点”之间的小偏差留缓冲，不是让车大幅倒着追路径。

- 更接近 0：几乎不允许回退，进度更单向
- 更负一些：容错更大，但可能导致局部来回修正感更明显

一般情况下这个值不需要改太多，除非你遇到路径附近短时抖动时进度切换太僵硬。

### 5. 前瞻与曲率

#### `_lookahead_min = 0.08f`
最小前瞻距离，单位米。  
即使速度很低，控制器也会稍微往前看一点，避免贴点式控制太死板。

#### `_lookahead_max = 0.30f`
最大前瞻距离，单位米。  
速度越高，前瞻点越远，但不会无限往前看，防止切弯过头。

#### `_lookahead_gain = 0.18f`
前瞻距离随速度变化的增益。  
它决定“速度快时前瞻多远”。

#### `_curve_lat_accel = 1.60f`
曲率限速对应的允许横向加速度，单位 `m/s^2`。  
曲率越大，允许的前进速度越低，这样弯道会更稳。

### 6. 完成判定

#### `_pos_tol = 0.01f`
终点位置阈值，单位米。  
表示距离终点位置小于这个值时，才算位置满足完成条件。

- 数值增大：更容易判定完成
- 数值减小：要求更严格，终点停车更准

如果终点总是差一点点不结束，先看这个。

#### `_yaw_tol = 0.02f`
终点姿态阈值，单位弧度。  
表示终点朝向误差小于这个值时，才算姿态满足完成条件。

- 数值增大：更容易结束
- 数值减小：更严格，要求车头对得更准

如果终点位置到了，但姿态就是差一点而卡住，优先看这个。

#### `_finish_progress_margin = 0.05f`
末端进度窗口，单位米。  
只有当投影进度已经进入路径末端附近时，才开始考虑完成判定。

它的作用是防止车辆在路径中段偶然靠近终点位置，却过早结束。

- 数值增大：更容易进入完成判定
- 数值减小：更强调“真的走到最后一小段”

#### `_finish_hold_ticks = 15`
完成保持周期。  
终点位置和姿态都满足后，还要连续满足一段时间，才会真正置为完成。

这一步是为了滤掉短时抖动，避免“刚到一下又抖出去”导致完成状态来回跳。

按当前 200Hz 更新频率估算，`15 tick` 大约相当于 `75ms` 的保持时间。

- 数值增大：完成判定更稳，但会稍微晚一点结束
- 数值减小：更快结束，但抗抖动能力变差

### 7. 调参建议

如果你第一次调这个模块，建议按下面顺序来：

1. 先保证路径数据本身合法，时间戳严格递增，起终点正确
2. 先调 `_lookahead_min`、`_lookahead_max`、`_lookahead_gain`，把“看多远”定住
3. 再调 `_kp_pos` 和 `_max_pos_fb`，让车能贴住曲线
4. 再调 `_kp_yaw` 和 `_max_yaw_fb`，让车头更稳地跟随路径规划朝向
5. 再调 `_curve_lat_accel`、`_max_vel`、`_max_omega`、`_max_s_dot`，把弯道速度和整体动作速度定下来
6. 完成判定不稳定时，再调 `_pos_tol`、`_yaw_tol`、`_finish_progress_margin`、`_finish_hold_ticks`

### 8. 常见现象和对应参数

- 车总是跟不上路径，越跑越偏
  - 先增大 `_kp_pos`
  - 再适当增大 `_max_pos_fb`
  - 如果响应还是慢，再适当增大 `_lookahead_min` 或 `_lookahead_gain`

- 车拐弯时左右摆动明显
  - 先减小 `_lookahead_max`
  - 再减小 `_kp_pos`
  - 再减小 `_max_pos_fb`
  - 如果是朝向抖，减小 `_kp_yaw` 或 `_max_yaw_fb`

- 车头转得太猛
  - 减小 `_kp_yaw`
  - 或减小 `_max_yaw_fb`
  - 还可以降低 `_max_omega`

- 路径前瞻太激进，底盘还没贴回曲线就提前切过去了
  - 减小 `_lookahead_max`
  - 减小 `_lookahead_gain`
  - 适当减小 `_max_s_dot`
  - 必要时降低 `_curve_lat_accel`

- 到终点了但一直不判定完成
  - 放宽 `_pos_tol`
  - 放宽 `_yaw_tol`
  - 放宽 `_finish_progress_margin`
  - 或减小 `_finish_hold_ticks`

## 对外接口

`PathChaserType` 提供的核心接口：

- `ChasePath(const Path<N>& path)`：设置路径并重置状态
- `Reset()`：手动重置内部状态
- `IsFinished()`：是否完成路径
- `GetCmdWorld()`：世界系命令 `(vx, vy, omega)`
- `GetCmdBody()`：车体系命令 `(vx, vy, omega)`
- `GetCmd()`：同时获取世界系 + 车体系命令

全局实例：

```cpp
APP::path_chaser
```
