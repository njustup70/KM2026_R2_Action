# PathChaser

`PathChaser` 是一个轻量路径跟踪库。  
输入是一组离线路点（包含位置、姿态、前馈平移速度、前馈角速度、时间戳），输出是当前时刻“建议控制量”。

本模块 **不直接控制底盘**，只负责 **产出命令**；上层可自行决定如何使用这些命令。

## 使用示例

```cpp
// 提前写好的路点
static const Path<4> demo_path = {{
    {{0.0f, 0.0f}, 0.0f, {0.4f, 0.0f}, 0.0f, 0.0f},
    {{0.5f, 0.0f}, 0.0f, {0.4f, 0.0f}, 0.0f, 1.2f},
    {{1.0f, 0.2f}, 0.1f, {0.3f, 0.1f}, 0.2f, 2.6f},
    {{1.2f, 0.4f}, 0.2f, {0.0f, 0.0f}, 0.0f, 3.0f},
}};

void StateAct_1()
{
    // 启动路径追踪，直接生效
    APP::path_chaser.ChasePath(demo_path);

    // 转移到 StateAct_2 ...
}

void StateAct_2()
{
    Vec3 cmd_body = APP::path_chaser.GetCmdBody();

    // 由用户决定是否直接下发，或用作其他用途
    // APP::chas.Move(cmd_body);   
}
```

## 数据结构

## 路点

```cpp
struct PathWaypoint
{
    Vec2 pos;       // 位置（m）
    float yaw_rad;  // 朝向（rad）
    Vec2 vel_vec;   // 前馈平移速度（m/s）
    float omega_rad;// 前馈角速度（rad/s）
    float t_sec;    // 时间戳（s）
};
```

## 路径

```cpp
template <size_t waypointCount = 256>
class Path
{
public:
    PathWaypoint waypoints[waypointCount];
};
```

说明：
- `Path` 是编译期定长数组，避免动态分配。
- 建议按 `static const Path<N>` 方式定义，减小 RAM 压力。

## 跟踪逻辑

每个周期主要流程如下：

用当前位置做最近点投影，得到实测进度 `s_meas`

按运行时间 `t_now` 映射得到参考进度 `s_ref`

融合推进得到控制进度 `s_cmd`：
`s_cmd_dot = v_ref + k_t * (s_ref - s_cmd) + k_m * (s_meas - s_cmd)`

按 `s_cmd` 采样目标状态：`pos_ref / vel_ff / yaw_ref / omega_ff`

计算误差并生成命令：
- `v_world = vel_ff + pos_fb`（`pos_fb = kp_pos * pos_err` 后单独限幅）
- `omega = omega_ff + yaw_fb`（`yaw_fb = kp_yaw * yaw_err` 后单独限幅）
- 再做全局线速度与角速度限幅

时间接近末端且终点误差满足阈值保持一段时间后，判定完成

## 调试参数说明

`PathChaser` 里这些成员变量，主要可以分成 4 组：

1. 路径跟随强度
2. 目标进度推进速度
3. 速度 / 角速度限幅
4. 完成判定条件

下面按“你改它会看到什么现象”的方式说明。

### 1. 路径跟随强度

#### `_kp_pos = 1.5f`
位置误差反馈增益。  
作用是把“当前目标点和实际位置的偏差”转换成补偿速度。

- 数值增大：车会更积极地往路径上拉回去，偏差修正更快
- 数值过大：容易出现横向抖动、过冲、拐弯时来回修正
- 数值过小：车会显得“跟不紧”，偏离路径后回正慢

这个参数主要影响的是：
- 路径贴合度
- 抗扰动能力
- 拐弯时的收敛速度

#### `_kp_yaw = 2.0f`
姿态误差反馈增益。  
作用是把“当前朝向和路径参考朝向的误差”转换成补偿角速度。

- 数值增大：车头对齐更快，转向更果断
- 数值过大：容易出现原地甩头、朝向抖动、转角来回修正
- 数值过小：朝向跟随滞后，尤其是转弯或终点对姿态要求高时更明显

这个参数主要影响的是：
- 车头对向稳定性
- 转弯姿态收敛
- 终点朝向完成情况

#### `_max_pos_fb = 0.15f`
位置反馈速度上限。  
这是 `_kp_pos * pos_err` 之后，单独给位置反馈项做的限幅。

它的意义不是“提高速度”，而是防止位置误差太大时，反馈项直接把速度拉满，导致长期猛追。

- 数值增大：允许更强的位置纠偏
- 数值减小：纠偏更保守，轨迹更平滑，但回正更慢

如果你发现：
- 一偏离就猛冲
- 拐角处横向修正太激进

通常优先考虑减小这个值，而不一定先改 `_kp_pos`。

#### `_max_yaw_fb = 0.5f`
姿态反馈角速度上限。  
这是 `_kp_yaw * yaw_err` 之后的限幅。

- 数值增大：允许更快修正朝向
- 数值减小：朝向修正更平稳，但可能跟不上路径转向

如果底盘转头太猛、容易左右摆，先看它。

#### `_yaw_ff_degrade_range = 0.3f`
Yaw 前馈衰减范围，单位弧度。  
按代码里的设计意图，它本来是用于“yaw 误差较大时，逐步减小角速度前馈”的。

不过要注意：**当前实现里这段前馈衰减逻辑被注释掉了**，所以这个参数现在基本是预留项，不会直接影响控制输出。

如果后续把那段逻辑恢复了，它的含义会变成：
- yaw 误差小于该范围时，前馈逐步恢复
- yaw 误差大于该范围时，前馈趋近于 0

### 2. 目标进度同步

#### `_k_sync_time = 0.5f`
和“时间参考进度”同步的增益。  
代码里会根据路径规划时间 `s_ref` 和当前控制进度 `s_cmd` 的差值，去修正目标进度速度。

它的作用是：
- 让轨迹更愿意按“计划时间”往前走
- 防止因为位置反馈太强，导致进度一直拖后

- 数值增大：更重视时间表，路径推进更“按表走”
- 数值减小：更放任实际位置决定进度，路径推进更柔和

如果车总是“追得太慢”，但路径本身又希望按时走完，可以适当增大它。

#### `_k_sync_meas = 0.5f`
和“实测进度”同步的增益。  
这里的实测进度 `s_meas` 是通过当前位置投影到路径上得到的。

它的作用是：
- 让控制进度更贴近真实位置
- 防止控制目标和实际位置差得太远

- 数值增大：更重视当前实际位置，路径跟踪更贴地
- 数值减小：更重视时间规划，轨迹更像预设时间轴驱动

这两个同步增益经常是成对调的：
- 如果要“更准地贴路径”，可以适当提高 `_k_sync_meas`
- 如果要“更严格按时间完成”，可以适当提高 `_k_sync_time`

### 3. 速度和角速度限幅

#### `_max_vel = 999.9f`
合速度上限。  
这是最终世界系线速度向量 `v_world` 的总长度上限。

注意它限制的是“合速度大小”，不是单独限制 `vx` 或 `vy`。

- 数值增大：允许更大的平动速度输出
- 数值减小：整条轨迹会更保守

如果底盘动力不足、轮子容易打滑、或者希望整体动作更稳，这个值是重要安全阀。

#### `_max_omega = 999.9f`
角速度上限。  
这是最终输出角速度 `omega` 的上限。

- 数值增大：允许更快转向
- 数值减小：转弯更平滑，终点姿态更稳

如果转向过激、姿态抖动、或者 IMU/控制链路还没调稳，建议先压低它。

### 4. 进度速度限制

#### `_max_s_dot = 1.20f`
控制进度速度上限。  
`_s_cmd` 是“沿路径走到哪里”的内部控制量，`_s_dot_cmd` 是它每秒推进多少。

这个值决定路径追踪器最多允许自己“沿路径往前推进多快”。

- 数值增大：路径推进更快，系统更激进
- 数值减小：路径推进更慢，更容易跟住，但可能拖慢整条任务

如果你发现车身还没对准，路径进度就已经跑太快了，适当减小这个值。

#### `_min_s_dot = -0.15f`
控制进度速度下限。  
它允许 `_s_cmd` 在某些情况下轻微回退。

这个回退量主要是给“位置实测进度”和“时间参考进度”之间的小偏差留缓冲，不是让车大幅倒着追路径。

- 更接近 0：几乎不允许回退，进度更单向
- 更负一些：容错更大，但可能导致局部来回修正感更明显

一般情况下这个值不需要改太多，除非你遇到路径附近短时抖动时进度切换太僵硬。

### 5. 完成判定

#### `_pos_tol = 0.02f`
终点位置阈值，单位米。  
表示距离终点位置小于这个值时，才算位置满足完成条件。

- 数值增大：更容易判定完成
- 数值减小：要求更严格，终点停车更准

如果终点总是差一点点不结束，先看这个。

#### `_yaw_tol = 0.05f`
终点姿态阈值，单位弧度。  
表示终点朝向误差小于这个值时，才算姿态满足完成条件。

- 数值增大：更容易结束
- 数值减小：更严格，要求车头对得更准

如果终点位置到了，但姿态就是差一点而卡住，优先看这个。

#### `_finish_time_margin = 0.05f`
完成时间容差，单位秒。  
代码里不是一到终点就结束，而是要求“时间也接近路径末端”。

它的作用是防止车辆提前因为位置刚好满足就过早结束，尤其是路径前半段速度规划比较快时。

- 数值增大：更容易在略早一点时也参与完成判定
- 数值减小：更强调严格到达末端时间

#### `_finish_hold_ticks = 15`
完成保持周期。  
终点位置和姿态都满足后，还要连续满足一段时间，才会真正置为完成。

这一步是为了滤掉短时抖动，避免“刚到一下又抖出去”导致完成状态来回跳。

按当前 200Hz 更新频率估算，`15 tick` 大约相当于 `75ms` 的保持时间。

- 数值增大：完成判定更稳，但会稍微晚一点结束
- 数值减小：更快结束，但抗抖动能力变差

### 6. 调参建议

如果你第一次调这个模块，建议按下面顺序来：

1. 先保证路径数据本身合法，时间戳严格递增，起终点正确
2. 先调 `_kp_pos` 和 `_kp_yaw`，让车能“跟住”
3. 再调 `_max_pos_fb` 和 `_max_yaw_fb`，压住过激修正
4. 再调 `_k_sync_time` 和 `_k_sync_meas`，决定更偏时间表还是更偏实测
5. 最后再收 `_max_vel`、`_max_omega`、`_max_s_dot`，把整体动作速度定下来
6. 完成判定不稳定时，再调 `_pos_tol`、`_yaw_tol`、`_finish_hold_ticks`

### 7. 常见现象和对应参数

- 车总是跟不上路径，越跑越偏
  - 先增大 `_kp_pos`
  - 再适当增大 `_max_pos_fb`
  - 需要时再增大 `_k_sync_meas`

- 车拐弯时左右摆动明显
  - 先减小 `_kp_pos`
  - 再减小 `_max_pos_fb`
  - 如果是朝向抖，减小 `_kp_yaw` 或 `_max_yaw_fb`

- 车头转得太猛
  - 减小 `_kp_yaw`
  - 或减小 `_max_yaw_fb`
  - 还可以降低 `_max_omega`

- 路径推进太快，底盘还没摆正就冲过去了
  - 减小 `_max_s_dot`
  - 适当减小 `_k_sync_time`

- 到终点了但一直不判定完成
  - 放宽 `_pos_tol`
  - 放宽 `_yaw_tol`
  - 或减小 `_finish_hold_ticks`

## 对外接口

`PathChaserType` 提供的核心接口：

- `ChasePath(const Path<N>& path)`：设置路径并重置状态
- `Reset()`：手动重置内部状态
- `IsFinished()`：是否完成路径
- `GetCmdWorld()`：世界系命令 `(vx, vy, omega)`
- `GetCmdBody()`：车体系命令 `(vx, vy, omega)`
- `GetCmd()`：同时获取世界系 + 车体系命令

全局实例：

```cpp
APP::path_chaser
```
